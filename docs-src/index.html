Aether — Autonomous Entity for Human-Aligned Enterprise Realization

Ein lokal prüfbarer Prototyp für kontrollierte KI-Koordination: ein planender Datenfluss mit menschlicher Freigabe, globalen Vetos und ergebnisprüfenden Gates — bewusst ohne Worker, Modelle, Netzwerke oder autonome Taten.

Python 3.9+, stdlib only 12/12 Unit-Tests bestanden (Sandbox-Lauf 2026-10-01) Python↔JS-Port: 66/66 Schritte paritätisch keine Produktionsfreigabe kein Tracking · keine externen Ressourcen
Maximiere Nutzen und Autonomie für den einzelnen Menschen,

minimiere die Möglichkeit, dass das System selbst zu einem neuen Macht- und Ausbeutungsinstrument wird.

Was dieser Prototyp ist

Eine validierte Neun-Task-Planstruktur, eine Bibliothek für Freigabe-, Veto- und Prüfsperren (aether/planner.py), dokumentierte Rollen (NEXUS, FORGE, PRISM, AEGIS, PULSE) und vollständig lesbare Datenverträge, Logs und Prüfberichte.

Was er nicht ist

Kein laufendes Unternehmen, keine parallelen Agentenprozesse, keine Modellläufe, keine Authentifizierung, keine Sandbox gegen lokalen Code und keine Abnahme. „Parallelität“ hier heißt: gleichzeitig bereitstehende Tasks, nicht aktive Worker.

Demo

Interaktive Browser-Demo

Freigabesperren, Vetos und Overrides selbst bedienen — auf einem getreuen Port von planner.py, komplett offline lauffähig. Inklusive „Ersten Lauf nachspielen“.

Skript-Transkript

Die echte Bibliothek, deterministisch durchgespielt von demo/run_demo.py: blockierte Aufrufe, Freigabe mit j, Veto, Override, Pause — als mitgelaufenes Protokoll.

Artefakte im Original

Plan, Freigabe, Ergebnisse result_t0…t8, Reviews, Summary und Run-Log — unverändert eingebettet, damit jede Aussage auf der Seite prüfbar bleibt.

Lokal ausführen (Voraussetzung: Python 3.9+, keine Pakete)

# Tests der Bibliothek
cd aether
python3 -m unittest discover -s . -p 'test_*.py' -v

# Skriptierte End-to-End-Demo der echten Gates
python3 demo/run_demo.py

# Parität Python-Original ↔ Browser-Port (benötigt Node.js)
python3 tools/parity_check.py

# Statische Seite neu bauen (Schreibzugriff nur auf docs/)
python3 tools/build_site.py

Governance-Rahmen der Demo

RegelGrenze
A-01Maximal 20 Tasks pro Plan; Validierung lehnt größere Pläne ab.
A-02Jede Entscheidung und jeder Task braucht ein nicht-leeres reason-Feld.
A-03Kein Tracking, keine Telemetrie, keine Paywall, kein Vendor-Lock, keine Cloud-Pflicht, keine Obfuskation — auch nicht auf dieser Seite: sie lädt ausschließlich eigene Dateien.
A-04Menschliche Kontrolle: Freigabe nur per exaktem j, globale Vetos, Override nur per override <ID>, Pause jederzeit.
